# 教材要放哪裡

有兩個地方可以放教材，用途不同，不要混淆。

## GitHub 的 kb/ 資料夾（正式用）

**所有學生都看得到，永久保存。** 這是正式的做法。

```
somm-tutor/
  index.html
  kb/
    manifest.json     ← 教材清單
    service.md
    pairing.md
    你的教材.md
```

`kb/manifest.json` 要列出每一個檔案：

```json
{ "files": [
  { "file": "service.md", "name": "侍酒服務流程講義" },
  { "file": "你的教材.md", "name": "顯示給學生看的名稱" }
] }
```

`file` 要和實際檔名完全一致，**大小寫也要一樣**。`name` 是引用時顯示的教材名稱。

網頁開啟時會自動讀取並索引，不需要任何操作。

## 教師介面的上傳（暫時用）

**只存在你這台電腦的瀏覽器，學生看不到。**

適合的情境：課堂上臨時補一段說明、測試某份教材的檢索效果。

不適合的情境：正式的課程教材。清除瀏覽器資料、換電腦、換瀏覽器，全部會消失。

## 把已上傳的教材轉成正式教材

如果你已經用教師介面傳了很多檔案，想改成正式的：

1. 教師模式 → 教材管理 → 按「匯出 kb/manifest.json」
2. 把下載到的 `manifest.json` 和你原本的 `.md` 檔一起上傳到 GitHub 的 `kb/` 資料夾
3. 重新整理網頁，教材管理頁上方會顯示「已自動載入 N 份教材」

匯出的 manifest 會沿用你上傳時的檔名。若原始檔名和 GitHub 上的不一致，要手動改一下。

## 怎麼確認真的生效

教師模式 → 教材管理，最上方的狀態框會顯示：

- 成功：「已自動載入 N 份教材，共 M 個片段」，逐檔列出片段數
- 失敗：直接寫出原因，例如檔名不符、JSON 格式錯誤

來自 `kb/` 的教材在清單中會標示「來自 kb/」，和瀏覽器暫存的區分得出來。

## 注意

GitHub Pages 是公開的，`kb/` 裡的教材任何人都能直接下載。有版權疑慮的講義不要放。
